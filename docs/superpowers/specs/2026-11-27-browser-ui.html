MacMaid: moving everything into the browser

Card lniVMHcS asks to move scan, report and clean into the browser and replace the terminal screens. Nothing has been built. Recommended: 1A 2A 3A.

1What happens to the terminal screens?

Recommended: A. Pick B only if you never want to clean from a terminal again. Pick C if you only want to see more categories in the page you already have. Pick D if the terminal and the current review page are enough.

2What may the browser delete?

Recommended: A. Pick B only if you need to free space at once and accept that it cannot be undone. Pick C if you want the browser to be unable to delete the automatic junk categories.

3Where does the scan run from?

Recommended: A, because the card asks for the whole flow in the browser. Pick B for a smaller first version. Ignored if you chose C or D on question 1.

Today

The terminal runs the scan and asks about each category, and each item in the review categories. The browser page shows only Large & Old Files and Duplicates, from the last saved scan.

What would be built (1A or 1B)

  • One tab per category with results, plus a summary of sizes.
  • Information-only categories (disk health, memory, thermal, login items) are shown with no delete control.
  • The nightly run and its email stay as they are, including the plain-text report.

Safety work this needs

  • The server must send each item to the cleaner with its category action. The review page does not do this today, which is harmless for its two categories but would try to move the Trash folder itself into the Trash.
  • Delete and quit requests need a per-session secret and a check of the address they came from, because the page would be able to delete far more.
  • The existing 24px dark readability test covers every new view.
