# MacMaid — Claude Context

## What This Project Is
A macOS maintenance tool. `main.py` opens a browser app that scans, reports and cleans; `--terminal` keeps the Rich terminal flow, and `--unattended` the scheduled one.

## Architecture

```
main.py          — CLI entry point; orchestrates scan → report → clean flow
config.py        — JSON config loader with defaults; always read inside scan(), never at module level
config_cli.py    — `main.py config` show/get/set/unset; a new setting must be added to its key sets
cleaner.py       — send2trash (default) or permanent delete; returns CleanResult dataclass; log_errors() is the one error log writer, for browser, terminal and nightly cleans
reporter.py      — Rich panels/tables/progress; print_unattended_report() for text reports
emailer.py       — thin wrapper around ~/.claude/utils/send_email.py
scheduler.py     — builds and installs LaunchAgent plist; _resolve_python() picks venv Python
fda_launcher.py  — builds ~/.local/share/MacMaid Storage Check.app (compiled C, ad-hoc signed com.macmaid.storage-check) that the hourly agent runs, so Full Disk Access can be granted to it alone
storage_watch.py — hourly low-storage check (`--storage-check`, LaunchAgent com.macmaid.storage); emails + notifies below storage_warn_gb / storage_urgent_gb
history.py       — appends JSON run records to ~/Library/Logs/mac-maid-history.json
reviewer.py      — Flask local server + embedded HTML/JS page. start(categories) serves a saved scan's review categories (`--review`, the email link); start_app(modules, scan) is the full app: the page scans, summarises and cleans every category
url_handler.py   — creates ~/.local/share/MacMaid.app bundle and registers macmaid:// URL scheme via lsregister
modules/         — one file per scan category, all expose scan() -> dict
tests/           — one test file per module; run with pytest (configured in pyproject.toml). conftest.py isolates the git environment for the dev_junk tests only
```

## Module Contract
Every `modules/*.py` must expose `scan() -> dict` returning a result from `make_result()`:
- `risk`: `"safe"` | `"review"` | `"inform-only"`
- `action`: `"trash"` | `"empty-trash"` | `"none"`
- `items`: list of `make_item()` dicts

## Current Modules (15)
`caches`, `logs`, `trash`, `downloads`, `large_files`, `duplicates`, `dev_junk`, `browsers`, `mail`, `login_items`, `disk_health`, `memory`, `thermal`, `ios_backups`, `xcode_sims`

Register new modules in the `MODULES` dict at the top of `main.py`.

## Key Rules
- **The browser deletes permanently only when emptying old Trash, and the cleaner gets each item with its own category's `action`** — `/api/delete` takes `{tab, paths}` and looks paths up in that tab only (the page always sends a tab; a request without one searches every tab); `action: "none"` is refused, `"empty-trash"` needs `empty_trash: true` (the page's Empty old Trash button and its own confirm), and nothing is deleted, nor the server stopped by Done, while a scan runs. An emptied Trash folder stays listed if any entry in it failed. Without the action tag the Trash folder itself would be sent to the Trash. `--permanent` and `permanent_delete: true` therefore route to `--terminal`, and `--dry-run` without `--unattended` is refused (exit 2) before `--serve`, `--review` and both cleaning flows, since each can clean. A browser scan saves its results to `mac-maid-last-results.json`, so `--review` then shows it. `tests/test_app.py` holds these rules (each was mutated and caught), `tests/test_app_browser.py` drives the page
- **The review page takes every `risk="review"` result whose `action` is `"trash"`** (`main._load_review_categories`) — it can only move to Trash, so other actions stay out. A new category gets Name/Path/Size; add to `COLS`/`NOTES` in `reviewer.py` for extra columns, a caution line, or (`CONFIRMS`) extra confirm-box wording for something irreplaceable. `mail` and `ios_backups` items record `tree_state` (`base.tree_state()`: a fingerprint of every entry inside, read twice and refused if the readings differ; not the newest mtime, which a future-dated file pins); the cleaner leaves one alone if it differs or cannot be read, and one saved with only the old `tree_mtime`; a tree the scan cannot read fully is not offered
- **The review server trusts neither the host name nor a bare POST** — `reviewer._make_app` refuses any `Host` that is not localhost (DNS rebinding), and every POST needs the per-session token embedded in the page and, when it sends an `Origin`, a localhost one, so send it with the page's `post()` helper and handle `refused()`. `main._start_review_server` therefore replaces the old server by signalling the *listener* (`lsof … -sTCP:LISTEN`) only when its command line is this checkout's `main.py --serve`, not through `/api/quit`; if it cannot start one, the email carries no link
- **Interactive prompts go through `main._confirm()`** — `questionary`'s `ask()` answers `None` on Ctrl-C, which only skips to the next prompt, and a bare Enter takes the default, so `_confirm` makes the caller name one: No for Empty Trash, for every per-file prompt (a Trash move included) and for every deletion under `--permanent`; Yes for a whole safe category that goes to the Trash (Downloads also removes folders already empty) and for opening a review. Ctrl-C drops the batch being chosen and ends the run. `tests/test_interactive_e2e.py` drives the real `main.py` in a pseudo-terminal through `tests/interactive_runner.py`, which redirects every path outside HOME into the fixture — add a new such path there too. File names and error text are data to `rich`: pass them as `Text` or `escape()` them
- **Config is always read inside `scan()`**, not at module import time — module-level config globals will break tests
- **`dev_junk` fails closed** — for the artefacts it *walks* (`TARGET_DIRS` + `TARGET_EXTS`). The three static paths `scan()` appends by name (Xcode DerivedData, the pip cache, `~/.npm/_cacache`) are unconditional and bypass all of it, `is_removable()` included; they are vendor caches at fixed locations, so that is deliberate. For everything walked, the artefact is offered only when git tracks matching evidence **directly in its parent directory** — `package.json` for `node_modules`; a `.py` or a `PY_PROJECT_FILES` entry for `__pycache__`/`.mypy_cache`/`.pytest_cache`/`.pyc` (a frozen app ships bytecode with the source stripped, so a tracked README proves nothing) — and that entry must **exist on disk**, since `ls-files` reports the index, not the working tree. The resolved path must also be under no `INSTALLED_SOFTWARE_MARKERS` segment, no `HOME_INSTALL_ROOTS` subtree, and inside no `BUNDLE_SUFFIXES` bundle (`.app`, `.framework`, …). An ancestor `.git` is deliberately NOT enough: installed software lives untracked inside checkouts (`~/.claude/plugins/cache/…`, `.venv/…/site-packages/…`), and a `.git` at a broad scan root would otherwise bless everything under it.
  - **`node_modules` needs a second thing: the project must be finished with** (2026-09-08). A tracked `package.json` proves the tree can be *reinstalled*, not that it should be deleted, so on its own it selected exactly the live projects it was written to spare — one lost the same directory eight times, and 519 `node_modules` had accumulated in the volume Trash. It now takes **two** answers, both fail-closed. `_head_age_days()` (git `log --all -1`, so a checkout parked on a stale branch is not mistaken for an abandoned repository) must exceed `dev_junk_dormant_days`; **and** `_worked_on_recently()` must find nothing — it stats the project directory and **every immediate entry in it**, not just the tracked ones, because `git status` never reports a gitignored file, then asks `git status --porcelain -z -unormal` for work in flight anywhere in the repository: a tracked change counts however old it is, an untracked path only if written inside the window. git collapses a new folder to one line, so `_written_since()` reads the files inside it (never entering a `TARGET_DIRS` directory); a `could not open directory` warning counts as unanswered. The commit age and the status answer are cached by repository root, so a monorepo asks once. `.git` is excluded by name: its mtime moves when git takes a lock, so this module's own queries would otherwise make every repository look busy. `_dormant_days()` refuses 0, a negative, a bool, an infinity or a non-number in favour of the default, because each switches the protection off or raises mid-scan. The commit date is the right primary signal: measured 2026-09-08 on the real roots, all 22 offered `node_modules` sat in repositories committed to that same day, while tracked files in those same directories were up to 152 days old. Deliberately **not** applied to bytecode or tool caches, which cost seconds and no network to rebuild; a test pins that.
  - **The scan records a `node_modules`' mtime BEFORE it decides, and the cleaner re-checks it before deleting.** `_dir_size()` walks the whole tree, so a baseline read after it would record an install that finished *during* the walk as the safe state — the race would close itself invisibly. `cleaner._unchanged_since_scan()` then skips (into `CleanResult.changed_paths`, reported as "left alone", never as a duplicate) anything whose mtime has moved. Its limit is pinned by a test: a directory's mtime tracks entries added and removed, not a file rewritten deeper down. It is a last line; the dormancy rule is the guard.
  - **Accepted trade-offs of the activity vetoes: a gitignored file buried in a subdirectory is not seen; recent untracked work anywhere in a repository spares every `node_modules` in it; a permanently dirty repository never has its `node_modules` reclaimed**, nor does one whose checkout was refreshed inside the window; and a project that is only ever *run*, never written to, still can be. Under-cleaning is the intended direction. `python3 tools/redproof_dev_junk.py` breaks each of these rules in a throwaway copy of the repo and requires the tests to go red — 26 mutants, all caught.
  - **The cleaner asks the whole dormancy question again, uncached, just before it deletes a `node_modules`** (2026-11-27, Codex review card 8YIyT25R): the scan caches per repository root and may then wait hours behind the review page, so an edit in a sibling package since would go unseen. The item carries `meta.recheck_parent`; `cleaner._repo_still_quiet()` calls `dev_junk.still_project_junk()` and an active or unanswerable repository is left alone. The answers are fresh but the time is not: one `new_recheck_budget()` per `clean_items()` call carries the git and walk budgets across every recheck, so a monorepo cannot repeat a slow walk per package. The untracked-file walk in `_written_since()` is iterative and shares `WALK_SCAN_BUDGET_SECONDS` (60, a guess, not measured) across the scan; running out spares the repository and is counted into the suggestion.
  - For bytecode the evidence must be **its own** source: `mod.cpython-312.pyc` needs a tracked `mod.py`, and a `__pycache__` is offered only when *every* `.pyc` inside it maps to one — the cleaner removes the directory wholesale, so one orphan condemns it.
  - **Accepted trade-offs.** A genuine project under `~/bin`, `~/opt`, `~/go`, `~/.config` or `~/Library` is never offered (pinned by a test). A tool installed by `git clone` + `npm install` into a location none of those lists names still is — the known residual, not covered. Anything git cannot answer for — no binary, a hang, an operational failure, an exhausted `GIT_SCAN_BUDGET_SECONDS` — is declined and counted into the result's suggestion, so an incomplete scan does not read as a clean machine. `GIT_CEILING_DIRECTORIES` is honoured because it *restricts* discovery; stripped are the variables that redirect git to another index, change what `:(glob)*` means, or widen discovery (`GIT_DISCOVERY_ACROSS_FILESYSTEM`), and `LC_ALL`/`LANG` are pinned to `C` so the non-repository answer is not read in a translation
- **`duplicates` never reads an iCloud-only file** (`SF_DATALESS` in `st_flags`) — reading one downloads it, and with Documents in iCloud a stalled download hung an interactive scan for 30 minutes (2026-11-27, 27,909 such files); the nightly run never saw this because launchd cannot read Documents. The skipped count goes in the suggestion
- **`duplicates` lists one entry per real file** — symlinks are skipped and a repeated inode (overlapping `scan_paths`, hard link) is ignored and a hard-linked file is never offered, otherwise the only copy of a file is offered as its own duplicate. `cleaner._keeper_intact()` re-compares each duplicate with its keeper before trashing it
- **`caches` skips `PROTECTED_PREFIXES`** — top-level `Caches` entries whose name starts (case-insensitively) with `ms-playwright` or `cypress`: installed tool binaries that merely live there. Only immediate children are checked; both tools install at the top level. Binning `ms-playwright` nightly broke seomachine's browser suite 18 times (2026-09-14). pip, Homebrew, pnpm, node-gyp and deno stay sweepable: their tools re-fetch transparently, so losing them costs a download, not a failed run
- **Trash retention counts from when an item was binned** — `base.binned_before()` reads the Date Added attribute (`getattrlist`); a Trash move keeps the old mtime, so mtime alone deleted old files the same night. A later mtime anywhere inside also keeps the entry, as does a hard-linked file (Apple: Date Added is inconsistent for those); no Date Added (volume does not record it) keeps it for good. The scan says what it could not check (an unlistable Trash folder; entries with no reliable binned date or not fully readable) instead of reporting nothing old. Tests that backdate Trash entries use the `binned_when_modified` fixture
- **`downloads` is opt-in (`config.OPT_IN_MODULES`)** — the CleanUp cron still does this job, and the nightly LaunchAgent runs this checkout in place, so enabling it is a live change. Port of CleanUp: files older than 24h by mtime go to Trash; a red Finder tag keeps a file or a whole subtree; unreadable tags count as red; symlinks are skipped; an emptied folder is removed with `rmdir` (`cleaner._remove_empty_folder()`), never moved or recursively deleted, so a late arrival cannot go with it. Review candidates it already took are dropped by `main._without_moved()`. It must stay registered after `trash`, because moved files keep their old mtime and emptying afterwards would delete them in the same run
- **`storage_watch` alerts once per level** — state in `~/Library/Logs/mac-maid-storage-state.json`; a worse level alerts at once, the same level only after `storage_realert_hours`, and a failed email is not recorded so the next hour retries. A blank `email_report_to` means no email: the banner is the whole alert and counts as delivered. The banner is then retried next hour if macOS did not take it. The Full Disk Access advice appears only when Trash, Mail or the iPhone backups cannot be listed at all. A folder `du` cannot fully read is reported as "at least N GB" when what it did read is 0.1 GB or more, otherwise "could not be measured" — never as 0 GB. Under launchd macOS refuses `~/.Trash`, `~/Library/Mail` and the iPhone backups without Full Disk Access (measured 2026-11-27); an interactive run does not show this. The alert also counts local Time Machine snapshots, which can hold the space of deleted files. **The hourly agent runs `MacMaid Storage Check.app`, not Python** (2026-11-27, card 5YhIqK1s): macOS charges file access to the program launchd started and its children, so granting Full Disk Access to that app covers the check without giving it to every script run by Python. Its commands are compiled in (`--storage-check`, or the read-only `--storage-probe`; any other argument runs the check), it spawns Python rather than exec'ing it, with a fixed environment and `-E` (nothing from the caller reaches Python; hardened runtime on the app), and `build()` rebuilds only when the commands change, because a rebuild changes the signature and macOS drops the grant. The nightly clean deliberately stays on Python, without access (owner choice). Prove access from launchd with a one-off agent running the app with `--storage-probe`; a run from a terminal proves nothing, since the terminal's own access applies. **Accepted residual:** Python, `main.py`, the modules and the user-site packages it imports are all writable by the user, so anything running as the user can edit them and inherit the access on the next hourly run; integrity-binding that whole import tree was judged out of scope (Codex 2026-11-27). Still strictly narrower than granting Python itself. `--unschedule` moves the app to the Trash
- **Thermal requires passwordless sudo** — `_has_passwordless_sudo()` checks first and returns an inform-only result if unavailable
- **Scheduler uses `_resolve_python()`** — prefers active venv, then `.venv`/`venv` in project dir, then `sys.executable`
- **Tests patch at the `module.cfg.get` level**, not via removed module-level constants
- **`reviewer.py` embeds JS in a Python triple-quoted string** — `\'` inside `"""..."""` is just `'`, not an escaped quote; use `data-*` attributes + `addEventListener` instead of inline `onclick` handlers to avoid JS syntax errors
- **`save_results()` is skipped in dry-run mode** — `unattended_mode()` only writes `mac-maid-last-results.json` when `dry_run=False`
- **The app and review page and the report email have a rendered readability floor** (24px, 6:1, dark, canonical buttons) — `tests/test_ui_contrast.py` runs `tests/contrast_check.py` (a copy of the dashboard-ui harness) in headless Chrome. The page reads `tokens.css`; the email inlines the same hexes
- **`--schedule` registers the URL scheme** — re-run `--schedule` after a fresh install to create `~/.local/share/MacMaid.app` and register `macmaid://`

## Running the App
```bash
# Run main.py — must use this interpreter (has all deps installed):
/Library/Frameworks/Python.framework/Versions/3.12/bin/python3 main.py [flags]

# Key flags:
#   --unattended        silent scan + email report (saves results JSON for --review)
#   --dry-run           scan without cleaning (does NOT save results JSON)
#   (no flags)          open the browser app: scan, report, clean
#   --terminal          the same in the terminal (also implied by --permanent)
#   --review            open browser UI for last saved scan results
#   --schedule HH:MM    install LaunchAgent + register macmaid:// URL scheme
```

## Autonomy
Exhaust every automation path (API, CLI, MCP, scripted browser) before handing a task back. **Full rule:** `~/.claude/rules/common/autonomy.md`.



## Subagent Offloading

Dispatch to a subagent (not inline) when any trigger fires: reading >3 files for one question, open-ended search, multi-step research, any task >2 min, batch operations, or verifying external-system claims. Use `run_in_background: true` for long-running tasks. **Sonnet is the floor for all subagents — never Haiku.** **Full rule + exceptions:** `~/.claude/rules/common/subagent-offloading.md`.
